### A03 第一批实施记录（2026-11-01）

| 场景 | 修复前 | 修复后 |

| 取消时数据库阻塞或写入失败 | 取消信号等待事务完成 | 先通知本地适配器停止；公开终态和 DONE 仍等持久化确认 |

### H01 watchdog 隔离实施记录（2026-11-01）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| A 终态写库阻塞或终态 Hook 很慢 | 占住唯一 watchdog 线程，B 到期也可能收不到停止信号 | watchdog 只发本地信号，写库和终态 Hook 交给独立有界收尾池 |
| A 的其他保存占用任务状态锁 | watchdog 等该锁，A 的本地停止也被延迟 | 快速路径不获取该锁，取消可先通知适配器 |
| 收尾池线程和队列均满 | 缺少明确的隔离退路 | 已生效的停止信号保留，拒绝不 CallerRuns，维护入口补齐终态 |
| 超时唤醒原 worker，随后发生 CANCELLED/SHUTDOWN | 新路径可能丢失最初的超时原因 | 保留 DEADLINE_EXCEEDED，阻止迟到答复，持久终态和 DONE 只确认一次 |

新增 `agent.execution.termination`，默认 core=2/max=4/queue=32，沿用执行池排队/活跃指标与拒绝计数；单线程 watchdog 保持不变。没有数据库迁移、工具协议或前端改动。慢 Hook 仍占用收尾工作线程，池拥堵时公开终态可延后，但 watchdog 不等待慢收尾。取消回调限受信任的快速 Future/适配器取消，不允许注册业务 Hook 或慢 I/O；并非对任意第三方代码的强制终止。

验证已覆盖：写库与真实 AgentHook 阻塞时另一任务停止、同任务存储 monitor 占用、收尾池饱和后的维护补齐、原因保留与迟到答复、真实 MySQL 行锁下 A 解锁前 B 独立结束及唯一 DONE。定向回归 52 项全部通过；日志 `var/watchdog-isolation-storage-it.log`。本批仅本地实施，尚未推送部署；单写锁与重启恢复规则保持原样。

最终开启隔离 MySQL 8.4 / Redis 7.4 运行 Agent 全量 `verify`：365 项全部通过，失败/错误/跳过均为 0（本批新增 7 项，其中 MySQL 集成 19 项、Redis 集成 2 项均实际执行）。打包后离线冒烟通过，覆盖未授权拒绝、FAQ/Harness 与 SSE、私有报告及 Trace 关联/脱敏，付费模型调用 0。发布规则测试 4/4、工作树发布扫描与 diff 检查通过。日志 `var/watchdog-isolation-final-verify.log`、`var/watchdog-isolation-smoke.log`；验证后仅清理本轮创建的隔离容器及匿名数据卷。未做生产负载或任意第三方 Hook 强制终止验收。

## 用户限定范围：房间合批（本地实现，待发布）

- 调研依据：[goim 房间缓冲与时间/数量触发实现](https://github.com/Terry-Mao/goim/blob/master/internal/job/room.go)、[Netty ChannelGroup 批量写入与连接生命周期](https://netty.io/4.1/api/io/netty/channel/group/ChannelGroup.html)。仅借鉴房间聚合模式，本次不增加消息分发中间件、压缩、跨节点广播或慢连接降级。
- 新增 `RoomBatchBroadcaster`，统一管理房间成员和待广播批次。默认从第一条消息起等待最多 100 ms，达到 50 条或 16 KiB 提前发送；JSON 外壳、逗号和 UTF-8 正文都计入字节限制。时间、条数、字节阈值可通过业务环境变量配置，配置边界见前端 README 与 `.env.example`。
- 每个房间仅保留一个受条数/字节限制的待发送批次及一个定时器；房间内部追加/发送串行化。达到阈值立即发送，不另外堆积无界的待广播任务。取消的定时任务及时从调度器队列移除，过期回调不能影响下一批。
- 房间清空时取消计时并释放待发送数据；已入队的业务弹幕仍走原持久化链路。服务关闭时尝试发出待广播批次、关闭房间连接，再依序停止业务与 IO 线程；不承诺所有关闭中的客户端都已接收消息。
- 新协议 `type=5, data=[...]`，每条弹幕仍保留独立 ID 和播放时间；MQ 入队和消费者入库仍逐条执行，批次仅作用于实时广播。人数、认证错误和业务错误消息继续立即发送。
- 前端同时兼容旧单条 `type=2` 与新批次 `type=5`，一次处理混合作者的消息；自己的回显继续驱动原发送标记，他人的消息批量追加播放器。未引入独立 ACK，未修改历史查询、缓存完整性、历史/增量统一去重或按播放区间订阅。
- 回归新增后端 9 项、前端 4 项；覆盖时间/数量/字节触发、UTF-8 大小、房间隔离、空房间释放、过期定时器、关闭、顺序与并发不重不漏。确定性用例验证 100 条消息按 10 条/批输出 10 帧，这是批次行为验证，不是线上容量压测。

## 后续候选：原协作任务

先开 Issue 认领，避免多人修改同一个公共接口。以下是任务规格，还没有自动创建远端 Issue。首轮每人选择一个方向即可。

| 任务 | 范围与交付 | 验收条件 |
|---|---|---|
| 业务表迁移与本地环境 | 清点实体/Mapper SQL，提供完整迁移和本地依赖说明；不使用真实库导出 | 新环境能初始化并跑最小登录/视频/弹幕链路，且不包含凭据和个人数据 |
| 业务数据验收与索引 | 接入经授权的测试账号；检查实际 state/时区/索引；补对账报告 | 正确归属、撤权、边界日期、明细 COUNT 一致；报告脱敏并附查询计划 |
| Token/费用预算 | 在模型结果与 Hook 间增加用量和预算端口 | 超预算受控终止；缺失 usage 有明确语义；多轮用量可对账，不硬编码供应商价格 |
| 新业务 Tool | 增加一个有明确口径的只读指标，配套 Tool Schema/Skill/Prompt | 有权限负例、SQL 对账、证据引用；不修改循环以加入业务特判 |
| 真实模型评测 | 建立不含用户隐私的小型问题集与离线评分入口 | 覆盖澄清、改写保真、越权、提示注入和口径；默认不付费，真实评测显式启用 |
| 存储与集群恢复 | 明确任务租约、凭据上下文和实例归属 | 故障注入验证单任务唯一执行与终态；不持久化明文登录 Token |
| 平台安全治理 | 独立设计历史密码哈希迁移、WebSocket 可信身份及接口审查 | 兼容旧账号迁移、有越权回归；不要一次 PR 混入多个认证机制 |

每个任务的 Issue 需要写清：负责人、改动目录、输入输出、依赖、验收方式。跨模块契约先评审，接口稳定后实现可以独立推进。

暂不优先做多 Agent、完整 RAG 或复杂报表。先证明一个业务指标在真实环境里可授权、可追溯、可对账，再扩展能力。
