# 文本模型上下文预算

预处理（意图、理解、情绪）和主循环共用 `ModelContextBuilder`，在供应商请求之前构造受限的上下文视图。不会额外调用模型做摘要，也不修改会话库、运行中的 observations 或证据库。

## 配置

| 配置 | 环境变量 | 默认值 |
| --- | --- | --- |
| `agent.context.max-input-bytes` | `AGENT_CONTEXT_MAX_INPUT_BYTES` | 98304（96 KiB） |
| `agent.context.max-history-bytes` | `AGENT_CONTEXT_MAX_HISTORY_BYTES` | 16384（16 KiB） |

总上限测量最终 system/user messages 数组的 UTF-8 JSON 字节数，包含系统指令、输入 JSON 二次转义和消息结构。历史上限测量 memory 对象的 JSON 字节数。它们是可重复测量的字节限制，不是精确 Token 计数，也不包含供应商输出额度；模型的 `max_tokens` 和每任务 Token 账本仍独立生效。需要按实际模型窗口和输出上限留出余量。

配置必须满足：总上限 1024–4194304 字节，历史上限 0–总上限。历史上限 0 表示移除可裁剪的历史内容；版本、边界和 truncated 标记仍保留，所以 memory 元数据本身不必小于该值。

## 构造规则

1. 对输入建立独立 JSON 视图。当前问题、日期、已确认任务条件、可用工具、Skill 指令和业务证据始终完整保留。
2. `read_skill` 结果中的 `tool_schemas` 若与本轮 `tools` 中某项完全相同，移除重复项；同名但描述或 Schema 不同的项保留。
3. 历史超过自身上限时，先移除 olderSummary，再按原顺序移除最旧的完整 runId 对话轮次。新历史优先，消息文本不做截断。
4. 若完整请求仍超限，继续按同样规则移除旧历史。发生移除时设置 `memory.truncated=true`，保留原 version 与 boundary。
5. 若系统指令、当前问题、任务或证据等必要内容仍超限，返回 `MODEL_CONTEXT_TOO_LARGE`，不发送 HTTP 请求、不预留供应商 Token。不会截断 JSON 或静默删除证据字段。

直接调用 `DeepSeekClient.complete` 并自行提供 messages 的代码也经过最终大小检查，不能绕过发送边界。视觉图像与转写请求使用独立的媒体大小限制，不适用此文本上下文裁剪。

当前尚未引入大证据分页读取工具或有损证据摘要：统计值、来源、时间、采样口径、样本 ID、证据 ID、最近失败反馈均保留。这避免模型把部分数据误当成完整证据，也意味着超大证据会明确失败，需后续通过有权限的分页工具扩展。

## 观察与验证

模型 Span 输出 `context.input_bytes`、`context.output_bytes`、`context.byte_limit`、`context.history_removed`、`context.schemas_removed` 和 `context.changed`。history_removed 是裁剪操作数（摘要一次、每个完整对话轮次一次），不是消息条数。

定向验证：`mvn -B -ntp -f tianmu-agent/pom.xml -Dtest=ModelContextBuilderTest,DeepSeekAdapterTest test`。覆盖中文与 emoji、多层 JSON 转义、整轮历史裁剪、原始数据不可变、证据完整性、重复 Schema、超限网络拦截，以及预处理和主循环的实际 HTTP 请求视图。
