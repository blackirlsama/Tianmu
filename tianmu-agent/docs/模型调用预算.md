# 模型调用预算

每个运行任务共享模型调用次数上限。预处理、主循环、收尾、视频视觉及音频转写都占用额度；视频分析缓存命中不占用模型调用。`Snapshot.totalModelCalls` 包含视频与转写调用，`modelCalls` 仍表示主循环调用，`preparationCalls` 仍表示预处理调用。历史快照可以继续读取，不需要修改数据库表。

## Token 预留与结算

`harness.loop.max-tokens`（环境变量 `AGENT_MAX_TOKENS`）为每任务 Token 准入额度，默认 `0`，关闭 Token 上限以保持既有部署行为。

`harness.loop.token-reservation`（`AGENT_TOKEN_RESERVATION`）为每次供应商请求的预留量，默认 `8192`。并发分支共享同一本账，发送 HTTP 请求前原子预留。完整有效的 `prompt_tokens` 和 `completion_tokens` 返回后，用实际总量替换预留量；usage 缺失、部分返回、超时、传输异常或非法响应保留预留量，不能当作零消耗。供应商响应中的内容解析失败，也不会抹掉已经上报的 usage。

例如设置 `AGENT_MAX_TOKENS=32768`、`AGENT_TOKEN_RESERVATION=8192`，可以同时预留四次请求。每次完整结算后释放多余预留量。剩余额度不足时，在网络调用前返回 `MODEL_TOKEN_BUDGET_EXCEEDED`；实际结算超额时终止当前任务，不交付该结果。

这是估算准入控制，不是供应商账单的严格硬上限。视觉、音频和输入文本的实际 Token 可能超过固定预留量，已经发出的并行请求也可能继续产生消耗。应按模型与业务负载调整预留量。当前没有货币价格表或费用结算功能。

## 观察与恢复边界

根 Span 与 finish 节点增加 `budget.token_limit`、`budget.charged_tokens`、`budget.reported_calls` 和 `budget.unsettled_calls`。charged 包含完整上报用量和未结算预留，不能称为供应商实际账单；usage 原始统计仍独立保留。

调用次数写入现有任务快照。Token 账本仅属于本次进程内执行，通过任务上下文传播到并发工作线程，不写入模型 Prompt。当前没有在途任务自动重放，因此不支持重启后继续消耗原 Token 额度；未来实现恢复协议时必须一起持久化账本。

验证入口：`mvn -B -ntp -f tianmu-agent/pom.xml verify`。预算测试覆盖并发争用、缺失 usage、传输失败、超额、取消、调用次数与快照恢复；视频适配器测试覆盖发送前拦截和缓存命中不计费。
