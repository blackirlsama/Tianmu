# 缓存与 Q&A 准入

缓存只保存可重算的结果，不授予权限。Q&A 是有来源、有准入阈值的作者私有知识，不与分析缓存共用状态和失效规则。

## 缓存边界

| 内容 | 热层 | 持久层 | 失效与一致性 |
| --- | --- | --- | --- |
| 对话记忆 | 既有 Redis 窗口 | MySQL 对话记录 | 按会话版本和权限范围核对；数据库是事实来源 |
| 视频事实 | 演示/故障回退 Caffeine | 既有 `agent_video_content_cache` | 来源版本、区间、关注点和模型入键；MySQL 有效一天，进程内回退最多一小时 |
| 报告分类 | Caffeine 最多64项 | `agent_report_cache` | 快照摘要、作者、请求、解析后的时间区间、模型和指令版本入键；持久层一小时，配置持久层时热层最多30秒，无持久层时热层一小时 |
| 房间汇总 | 既有 Caffeine 与正在计算的任务 | SQL 原始互动仍是事实来源 | 最多100项、闲置15分钟过期；保留上次成功汇总及其时间 |
| 已加入 Q&A | 不缓存管理状态 | `agent_qa_catalog` | 每次按作者、有效期和当前阈值检查，停用后立即不再命中 |

报告使用 `AnalysisCacheStore` 作为可选持久化端口；`ReportAnalysisCache` 保留业务键与覆盖校验，`MysqlAnalysisCacheStore` 只负责存取、TTL、进度比较和计算租约。存储与业务分类相互独立，继续复用现有 Caffeine、JdbcTemplate 和 Flyway。

每次仍先鉴权、获取新互动快照及当前视频事实。命中后只恢复同一区间、相同原文、身份、数量、来源及回复上下文的分类，统计图表使用本次取数。缓存不保存旧运行的证据 ID；恢复时绑定当前运行。持久化进度必须覆盖已处理前缀，每个标识只出现一次，人数/次数及进度等级不一致时当作未命中。更慢的写入不能覆盖更新进度。相对时间请求解析出不同区间时不会复用旧叙述，重试同一区间应保留原任务的时间条件。

同一快照在开始分类时申请计算租约，后续批次和合并续租。租约持续两分钟，任务终态主动释放，进程退出后到期释放。MySQL 模式跨实例协调，内存模式只协调当前进程；重复任务返回 `REPORT_IN_PROGRESS`，不继续重复分类。申请租约前仍可能产生取数、读视频及一次模型编排调用，不宣称重复请求完全零成本。缓存数据库不可用时短暂退避并回落本地协调，任务预算继续生效。现有 Spring 调度器每分钟分批清理过期缓存和租约，每类最多1000行，不在模型循环内反复做全表清理。

缓存故障不改变鉴权结果，也不应使已成功计算的视频事实丢失。视频缓存写入失败可用进程内副本；报告缓存故障当作未命中。尚未实现变化语料的分区增量复用，语料变化仍重新分析。

## 按阈值自动加入 Q&A

不新增模型评分或向量调用。默认规则为：最近30天、最多256个独立会话的合格首轮回答中，相同问题至少有5个会话提供同一个答案，且该答案占比至少90%，自动变为 `ACTIVE`。有效期七天，过期后不直接回答。问题做 Unicode、空白和末尾问号规范化；答案按文本一致性判断，不把语义相近内容强行合并。

候选只来自已经成功交付的普通知识对话：首轮、正常回答终态、无业务证据。失败、取消、FAQ 自身命中和轮次耗尽收尾均不累计。包含时间依赖、业务统计、数字、链接或上下文指代的问答保守排除。频次和一致率只代表稳定性，不代表事实正确性，因此必须保留停用及重新学习入口，不能自动扩散为全站公共答案。

同一作者和同一问题按会话去重，重放相同运行不会增加票数。不同作者、租户完全隔离。MySQL 用问题聚合行锁串行处理观察去重、阈值计算和激活；不会出现并发重复计数后提前加入。状态最大256份观察，答案只保留这些观察引用的文本。

达到阈值后的请求仍经过当前身份认证。预处理先命中内置固定 FAQ，再查询作者已加入 Q&A；成功后返回 FAQ 路由，不读工具或调用模型。Q&A 不可用时作为 FAQ 依赖降级，按原流程继续，并保留用量限制；不会绕过授权失败。

观察写入通过 `RunCompletionListener` 在运行终态提交之后完成，不属于交付事务，失败不能反过来把成功回答变成失败。极端崩溃可能漏计；可通过 `from-run` 端点重放已拥有的运行来补计，仍执行资格检查与会话去重。当前不承诺观察事件恰好一次。

## 管理与配置

作者界面的“常见问答”展示候选次数、一致率及当前状态；停用后不再自动激活，重新学习则清空该问题积累。变更要求最新 `version`，跨作者返回不存在，旧版本返回冲突。Q&A 是独立知识，清理对话与停用/重置知识是不同的管理操作。

- `GET /api/agent/qa`：读取自己的策略与最近100个问题。
- `POST /api/agent/qa/from-run`：使用自己的 `runId` 补计合格回答。
- `POST /api/agent/qa/{id}/disable`：携带 `version` 停用。
- `POST /api/agent/qa/{id}/reset`：携带 `version` 清空并重新积累。

默认配置：`AGENT_QA_ENABLED=true`、`AGENT_QA_MINIMUM_SESSIONS=5`、`AGENT_QA_MINIMUM_ANSWER_SHARE=0.9`。窗口、有效期与聚合上限在 `agent.qa` 下配置。关闭开关会停止积累和直答，保留管理能力。

MySQL 模式由迁移 `V5__report_cache_and_qa_catalog.sql` 建立派生报告缓存、报告租约和私有 Q&A 表。内存演示模式只保存当前进程状态；不会在 MySQL 故障时把知识写入临时内存，避免产生两个知识事实来源。

本地测试覆盖阈值、冲突答案、独立会话去重、并发、有效期、作者隔离、停用/重置，以及加入后的零模型调用直答；专用 MySQL 集成测试需要显式配置测试库，不使用生产数据或付费 API。
